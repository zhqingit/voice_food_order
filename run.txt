
RUN backend:
  Easiest way — Docker (Postgres + API together):

  cd backend
  #docker compose down -v
  docker compose up --build

  This starts both PostgreSQL and the FastAPI server, and auto-runs migrations. Health check at http://localhost:8000/health.

  Without Docker:

  cd backend
  source .venv/bin/activate
  uvicorn app.main:app --reload

  (You'll need a running PostgreSQL instance and a configured backend/.env with DATABASE_URL pointing to it.)

  Key env vars to set in backend/.env:
  - DATABASE_URL — Postgres connection string
  - JWT_SECRET, REFRESH_TOKEN_PEPPER — Auth secrets
  - CORS_ORIGINS — Allowed origins
  - Voice-related keys (GOOGLE_API_KEY, etc.) if you want the voice pipeline

  Run migrations manually (if needed):

  cd backend
  alembic upgrade head

Step 6: Configure Environment

  On the VM, create the production .env:

  cd ~/voxeats/backend
  VM_IP=$(curl -s http://metadata.google.internal/computeMetadata/v1/instance/network-interfaces/0/access-configs/0/external-ip -H "Metadata-Flavor: Google")
  JWT_SECRET=$(openssl rand -hex 32)
  REFRESH_TOKEN_PEPPER=$(openssl rand -hex 32)
 
  cat > .env << EOF
  DATABASE_URL=postgresql+psycopg://postgres:postgres@db:5432/auth_template
  JWT_SECRET=${JWT_SECRET}
  REFRESH_TOKEN_PEPPER=${REFRESH_TOKEN_PEPPER}
  CORS_ORIGINS=*
  GEMINI_API_KEY=YOUR_GEMINI_KEY_HERE
  USER_API_HOSTS=user-api.local,${VM_IP}
  STORE_API_HOSTS=store-api.local,${VM_IP}
  WEB_RELOAD=false
  WEB_WORKERS=1

  EOF
 
  Then manually edit the GEMINI_API_KEY line:
  vi .env
  Note: removed the ' quotes around EOF so that the ${} variables get expanded. The Gemini key is left as a plain placeholder string (no <>) so it won't break — just replace it with your real key.

###### --------use e2-micro-------#####
 Problems with 1GB RAM:
  - Docker build alone can OOM (pip install + pipecat dependencies)
  - 4 gunicorn workers × ~150MB each = 600MB, plus Postgres = won't fit
  - Store portal Vite build also needs RAM

  Make it work:

  1. Reduce workers to 1-2 in your .env:
  WEB_WORKERS=1
  2. Add swap (run this on the VM before docker compose):
  sudo fallocate -l 2G /swapfile
  sudo chmod 600 /swapfile
  sudo mkswap /swapfile
  sudo swapon /swapfile
  echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
  3. Skip store portal container — build it locally and serve as static files instead, or just test the API + Flutter app:
  # Only start db + api
  #docker compose up --build -d db api

  Realistic expectation on e2-micro:
  - 1-3 concurrent voice calls: OK
  - API + store portal browsing: OK
  - Any real load testing: No

  My recommendation: Use e2-small (0.5 vCPU, 2GB RAM) — it's ~$13/month (vs $8 for micro) and avoids all the RAM headaches. It'll handle 2 workers + Postgres + store portal without swap tricks.
